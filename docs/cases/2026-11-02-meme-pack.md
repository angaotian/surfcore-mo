# 2026-11-02 · 表情包资源包导入（兼容 AstrBot meme_manager 的包格式）

> 来源：用户投喂的 `meme_manager-5.3.0`（AstrBot 表情包管理器）源码包，问「你看能不能优化兼容」；
> 选项里用户选了 **A+D**：A = SurfCore 直接吃它的资源包目录（带 AI 标注），D = 设置页拉社区索引一键装包（D 未开始）。
> 同一天用户还提了两件事（m00776）：**她要发得更多**、**能自己搜索收藏**；「表情包小偷」明确不要。

## 现象

- SurfCore 的表情库存只有「大肥鱼 24 张 + deepseek娘 18 张」两类，且都是手工塞进 `state/stickers.json` 的。
- 别人（AstrBot 生态）已经有一整套**资源包格式**：`manifest.json` + `memes/<分类>/<图>` + `semantic_metadata.json`
  （含 caption / tags / visible_text），社区索引托管在 GitHub raw 上，装包就是「把目录放到对的位置」。
- SurfCore 完全没有这个概念：`grep -r "manifest.json" src/` 只命中更新包与语音包的清单，表情包侧一个都没有。
- 影响面：只影响「表情包怎么进来」，不碰发送链路、不碰 prompt 之外的任何东西；导入失败只回错误码，不动已有库存。

## 环境

| 项 | 值 |
| --- | --- |
| 系统 / DSH 版本 | Windows / DSH（qq-chat-v2 预设） |
| SurfCore 版本 | 0.8.4（工作区有在途改动，未提交） |
| 安装方式 | junction：`~/.dsh/plugins/surfcore` → `E:\DSH-Data\surfcore\plugins\surfcore` |
| 被兼容方 | `meme_manager 5.3.0`（AstrBot 插件，Python，6.7MB） |
| 其它 | 桥接单实例；表情库是 `state/stickers.json`，写者只有桥接进程 |

## 根因（为什么现在没有）

- 不是 bug，是缺能力：SurfCore 的表情来源只有两条——手工写进 `stickers.json`、或从 QQ 收藏夹同步。
  两条都要求「图先在本地」，没有「按包导入一堆带标注的图」这条路。
- AstrBot 那套包格式其实**非常适合**当交换格式：纯目录、纯 JSON、标注与图分离，
  连「这张图什么情绪、什么时候用」都写好了（`semantic_metadata.json` 的 caption/tags），
  正好是 SurfCore 匹配调用时最缺的字段（见 `src/sticker-semantics.js` 的匹配逻辑）。
- 之所以不能直接把 AstrBot 插件装进来：它是 Python + AstrBot 的 pages 体系（`main.py` / `mixins/web_api.py`），
  DSH 插件是 Node + `ctx.webServer`，两套运行时。**能兼容的是格式，不是代码。**

## 完整逻辑（给用户看的那一遍）

- **链路**：设置页「表情包」标签 → 填目录（或点「浏览…」）→ 插件 `POST /dsh-surfcore/api/sticker-pack/import`
  → `callBridge('/api/stickers/pack-import', {body:{dir}})` → 桥接 `importMemePackDir(dir)`
  → `src/meme-pack-import.js` 扫目录、复制图、造条目 → `onSave` 里 `stickerEntries = next` +
  `ensureStickerIndex` + `saveStickerStoreSafe()` → 返回 `{added, skipped, total}` 给设置页。
- **机制**：包格式解析在 `src/meme-pack.js`（纯函数，可单测），文件 IO 在 `src/meme-pack-import.js`（依赖注入，可单测），
  桥接里只有一层薄包装（`src/bridge.js:2615` 附近）负责把 `STATE_DIR` / `stickerEntries` / `findSticker` /
  `detectEmotions` / `log` 注进去。**单写者不变**：`stickers.json` 仍然只有桥接进程写。
- **标注怎么来**：`semantic_metadata.json` 有 caption 就用 caption，没有退到 `memes_data.json` 的分类描述，
  再退到分类名；情绪用 SurfCore 自己的 `detectEmotions(caption+tags)` 判（20 类），判不出记 `neutral`；
  tags 统一追加 `[包名, 分类, 'meme-pack']`，这样「按 tags 统计图包」的提示词头部会自然多出一行。
- **爆炸半径**：新端点 + 新文件，不改 `stickerEntries` 的读路径；导入过程中任何一张图失败只计入 `skipped`；
  目录/清单不合法直接返回带 `code` + `hint` 的 `ok:false`，库存一个字节都不动。
- **取舍**：
  - A. 直接解析 AstrBot 的 SQLite/向量库 → 需要 Python 运行时，且版本一换就崩；B. 只吃目录格式（选中）→ 零依赖、可移植。
  - A. 把图留在原目录、只在 `stickers.json` 里存绝对路径 → 用户一删源目录表情就全废；
    B. 复制进 `state/sticker-files/<packId>/`（选中）→ 自包含，代价是占磁盘（上限 400 张 / 单张 4MB）。
  - A. 导入时调 VLM 重新描述每张图（贵、慢、要联网）；B. 先用包里已有的 caption/tags（选中）→ 秒级、离线可用；
    VLM 补标注留到「导入后按需」再做。
- **生效与重启**：桥接代码改动要**重启桥接进程**（PITFALLS #25）；插件侧（`lib/index.js` / `lib/client.js`）改动要重启 DSH。

## 修法

- 新增 `src/meme-pack.js`（纯函数）：`validatePackId` / `normalizePackManifest` / `packCategoryOf` /
  `parseSemanticMeta` / `stickerDraftFromMeme` / `packStickerId` / `normalizeImportItems`，
  常量 `PACK_MANIFEST_FILE` / `PACK_MEMES_DIR` / `PACK_MEMES_DATA_FILE` / `PACK_SEMANTIC_FILE` / `PACK_IMAGE_EXTS`。
- 新增 `src/meme-pack-import.js`（文件 IO，依赖注入）：`importMemePackDir(dir, {stateDir, entries, findSticker, onSave, detectEmotions, log})`，
  id + md5 双去重、`MAX_FILES=400`、`MAX_BYTES=4MB`、编号接着现有最大值往后排。
- `src/bridge.js`：import 段接 `meme-pack-import.js`；`importMemePackDir` 改成薄包装；
  新端点 `POST /api/stickers/pack-import`（在 `/api/stickers/remark` 之后），
  只读降级闸门把该路径也算进 `stickerStoreWritable`。
- `plugins/surfcore/lib/index.js`：`handleStickerPackImport`（GET 列出库存概览 / POST 转发导入）+ 路由
  `${API_PREFIX}/sticker-pack/import`；桥接不可达回 `STICKER_BRIDGE_UNREACHABLE` 502 带 hint。
- `plugins/surfcore/lib/client.js`：`StickersTab`（总数/分组/目录输入/浏览/导入/结果区）+ TABS 加「表情包」。
- 回滚：删 `src/meme-pack.js`、`src/meme-pack-import.js`，去掉桥接 import 与端点、插件路由与标签页；
  已导入的图在 `state/sticker-files/<packId>/`，删目录 + 从 `stickers.json` 删 `source:'pack'` 条目即可（纯派生数据）。

## 已知边界

- **只做 A（导入），D（社区广场）还没做**：设置页现在是「填目录/选目录」，不是「列表里点安装」。
  社区索引 URL 已经查清（`https://raw.githubusercontent.com/anka-afk/astrbot-meme-pack-index/main/community-index.json`），
  下一步是拉索引 + 下载 zip + 解压 + 复用同一个导入函数。
- 不跑 VLM：包里没有 caption 的图会用分类描述兜底，可能比图本身粗糙；要更准得靠 D 阶段后补标注。
- 不做「导出」：反向打包（把 SurfCore 现有 42 张导成 AstrBot 包）没做，等有人要分享再说。
- 图是**复制**不是引用：包目录删了不影响 SurfCore，但同一张图导入两次会靠 md5 去重，不会重复占空间。
- 打包/解压 zip 这一步没做：用户现在得先自己解压，再把目录指进来。
