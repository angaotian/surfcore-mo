# 2026-11-02 · 读法（思维链式消息防抖的 SurfCore 版）

> 来源：小黑盒帖子《安装插件给"小鲸鱼"deepseek完整的一生》第 11 个插件
> **思维链式消息防抖 1.3.1** ——「收到消息后 LLM 会像真人读消息一样逐条思考
> （逐条要点、总体判断、未决问题），并且会按照设定的人格改变思考风格」。

## 现象

- 群里一次涌进来 5 条、两个人同时说话、有人只说半句时，她容易答错人、漏掉一个问题、
  或者把最后一句当成全部意思。**不是理解能力问题，是没人要求她先读完**。
- 用户选了四项要搬进 SurfCore，这是第二项。

## 环境

| 项 | 值 |
| --- | --- |
| 系统 / DSH 版本 | Windows / DSH（qq-chat-v2 预设） |
| SurfCore 版本 | 0.8.4 + 本轮工作区改动 |
| 相关配置 | `socialV2.think`（新增，缺省即开） |

## 根因

- 「防抖」的一半 SurfCore 早就有：`socialV2.wait` 的静默窗口 + `buildBatchPrompt` 的批量唤醒，
  消息不会一条一条地喂给她。
- 缺的是另一半：**读**。旧 prompt 21 段里，讲「怎么回」的有六七段（反 AI 味、首回复节奏、
  表情策略、收尾判断），讲「怎么读」的一段都没有 —— 直接跳到「请回复消息」。
- 帖子那个插件是让模型每轮先输出一段思考；我们没有让它输出，只在 prompt 里**要求它先想**，
  因为把思考写进上下文既费 token 又容易漏到群里。

## 完整逻辑（给用户看的那一遍）

- **链路**：新消息到 → 唤醒 → `buildWakePromptV2` → `buildThinkBlock`（`src/think.js`）→
  未读数 > 0 才拼一段【读法】进 prompt → 模型先在心里过三步再决定发不发。
- **机制**：三步固定 = ①逐条要点（最多 N 条）②总体判断（要不要接/接哪条/回几条）
  ③未决问题（要不要反问）。风格按人格卡自动挑：毒舌/高冷 → dry（多一句「哪句最省字」），
  活泼/可爱 → chatty（多一句「有没有梗可接」），其余 brief（中性三句）。
- **爆炸半径**：只多一段约 120 字的 prompt；不新增状态文件、不新增进程、不改发送路径。
  没有未读消息（主动搭话 / 收尾 / 探针）时返回空串，一个字节都不多花。
- **取舍**：
  - A. 让模型把思考输出出来（帖子插件的做法）→ 思考会进上下文、可能漏到群里、还占输出额度；
    B. 只在 prompt 里要求它「心里过一遍」（选中）→ 零输出成本，行为靠指令约束。
  - A. 思考风格单独做一个设置项让人选 → 多一个没人调的开关；B. 从人格卡关键词自动判断（选中），
    配置里仍可用 `style` 强制覆盖。
- **生效与重启**：改的是桥接 prompt → **重启桥接进程**（PITFALLS #25）。
- **验证**：见下；手动验收 = 让群里两个人同时说两件不同的事，看她是否分别回应而不是只接最后一条。

## 修法

- 新增 `src/think.js`（纯函数，无 IO）：
  - `normalizeThinkConfig`：`{enabled:true, style:'auto', maxPoints:3}`，`maxPoints` 钳 2..5；
  - `thinkStyleOf(personaText, style)`：显式配置优先，否则按人格卡关键词（`DRY_RE` / `CHATTY_RE`）判断；
  - `buildThinkBlock({cfg, personaText, unreadCount, maxMsgs})`：0 未读或关闭 → `''`，
    否则返回【读法】段（以 `\n\n` 结尾）；
  - `thinkSnapshot`：设置页/诊断用的只读快照。
- `src/bridge.js`：import `buildThinkBlock`；在 `antiAiLine` 之后算 `thinkLine`（人格卡取
  `purposePersonaText()` 前 1200 字），`base` 串里插在 `antiAiLine + thinkLine + proactiveLine`，
  `lastWakePromptMeta` 补 `think` 长度。
- 测试：`scripts/test-think.mjs`（10 组）、`package.json` 注册 `test:think`。
- **测试夹具**：`scripts/audit-bridge-harness.mjs` 会剥掉 bridge.js 的顶层 import、靠 context 注入绑定。
  本轮补了 `...favor` / `...think` 两个模块的注入，以及 favor 的**别名**
  （`emptyFavorStore`/`decayFavor`/`normalizeFavorStore`/`observeFavorMessage`/`buildFavorPromptBlock`）——
  `import { x as y }` 在 VM 里只剩原名，别名不补就会报 "xxx is not defined"，上一轮好感度
  其实也踩了这个坑（只是被 try/catch 吞了，测试没暴露）。
- 回滚：`socialV2.think.enabled = false`（或整段删掉）→ prompt 立刻回到旧样子，代码不用动；
  要连代码一起回滚就 `git checkout src/bridge.js` 并删 `src/think.js`。

## 验证


覆盖：默认值 / 关闭 / 非法风格 / 要点数钳制 / 三种风格判定 / 显式风格覆盖 / 0 未读不注入 /
需要条数与实际上限同时生效 / chatty 与 dry 的第四条 / 人格卡自动选风格 / 快照。

## 已知边界

- 只接在 `buildWakePromptV2` 上。旧路径 `buildBatchPrompt`（`src/bridge.js:11286`）与
  `buildProactivePrompt` 没有接 —— 前者是三代之前的批量唤醒，后者是主动搭话（没有别人的新消息要读）。
- 「思考」不可见：没有把思考存下来给设置页看。想看它在想什么，只能看 `plugin.log` 的唤醒
  meta（里面有 `think` 段长度）。
- 风格判断是关键词匹配，人格卡写得很文艺时可能判不出来 → 落到 brief（中性，不会出错）。
- 不改防抖本身：静默窗口、合批、`qq_wait_for_messages` 的行为一点没动。
