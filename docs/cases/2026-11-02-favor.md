# 2026-11-02 · 好感度（EmotionAI Pro 的 SurfCore 版）

> 来源：小黑盒帖子《安装插件给"小鲸鱼"deepseek完整的一生》里的第 12 个插件 **EmotionAI Pro v4.2.6**
> ——「好感度越高，它越会记住并主动提起与你相处的细节，态度也更亲近；好感度低时只记得冲突」。
> 用户选了四项要搬进 SurfCore，这是第一项。

## 现象

- 用户原话（m00144）：「还是照着这篇帖子，把里面的插件、做法搬到 SurfCore 上？」
- 现状：小鲸鱼对所有人都一样热络，骂她一句和夸她一句在下一次唤醒里没有任何区别；
  群友 A 天天来聊天、群友 B 三个月没出现，她的语气完全一致。帖子里那套「关系会变」的能力，SurfCore 没有。
- 影响面：只影响「语气/记忆侧重点」，不碰消息投递、不花钱、不丢数据；关掉开关就回到旧行为。

## 环境

| 项 | 值 |
| --- | --- |
| 系统 / DSH 版本 | Windows / DSH（qq-chat-v2 预设） |
| SurfCore 版本 | 0.8.4（工作区有在途改动，未提交） |
| 安装方式 | junction：`~/.dsh/plugins/surfcore` → `E:\DSH-Data\surfcore\plugins\surfcore` |
| 其它 | 桥接单实例；状态在 `state/`，插件状态在 `~/.dsh/surfcore/` |

## 根因（为什么现在没有）

- 不是 bug，是缺能力：`buildWakePromptV2`（`src/bridge.js:13483`）拼了 21 段 prompt，没有一段讲「你和这个人是什么关系」。
- 记忆卡存的是**事**（谁说过什么），不存**关系**（我对这个人的感觉）。两件事维度不同：
  一件事很重要不代表关系近，一个人关系很铁也可能最近没说什么正事。
- 之前刻意没做，是因为「让模型自己给好感度打分」有两个坑：每轮多一次输出（贵且漂移）；
  数值写进 prompt 后模型会顺着它演（分数自证）。所以 v1 用**确定性规则**打分，模型只读。

## 完整逻辑（给用户看的那一遍）

- **链路**：QQ 消息 → 桥接 `appendSocialV2Message`（`src/bridge.js:13012` 附近）→ `noteFavorIncoming`
  → `src/favor.js` 的 `observeMessage` 打分 → `atomicWriteJson(state/favor/<角色>.json)`
  → 下一次唤醒 `buildWakePromptV2` → `favorPromptLine` → prompt 里多一段【好感度】。
  设置页：`GET /dsh-surfcore/api/favor` → 插件读同一个 JSON（只读）→ 「好感度」标签页。
- **机制**：单写者（只有桥接进程写），按角色分文件（换人格不继承关系值，PITFALLS #29），
  分数朝 50 回归而不是朝 0 掉（久不联系是变淡，不是变恨）。
- **打分信号**（全部可解释，写进 events）：在场 +0.15（每人每小时最多 10 条，防刷屏）、
  私聊/@/引用 +0.5、情绪浓度 +≤1、示好词（谢谢/可爱/厉害…）+1.5、冲突词（滚/傻逼/去死…）−3。
- **爆炸半径**：2 个进程读（桥接写、插件读）× 1 个文件；不改协议、不动发送路径；
  失败时 `noteFavorIncoming` 整段 try/catch，打分失败绝不影响收消息 → 静默分 3（最坏：好感度不涨）。
- **取舍**：
  - A. 让模型打分 → 每轮多一次输出、数值漂移、prompt 自证；B. 规则打分（选中）→ 便宜、可解释、可测。
  - A. 单文件存所有人 → 换角色继承（PITFALLS #29 同款事故）；B. `favor/<角色>.json`（选中）。
  - A. 插件直接读写这个文件 → 两进程写同一 JSON（PITFALLS #14）；B. 插件只读、桥接单写（选中）。
- **生效与重启**：改桥接代码要**重启桥接进程**（PITFALLS #25：热重载不清 src/ 的 ESM 缓存）；
  设置页插件改动要重启 DSH 让插件重新加载。

## 已知边界

- v1 只按**入站**打分：她自己的回复不加分，所以「她主动找话题」不会让关系变近（下一步可补 outbound 信号）。
- 不发消息的人不会衰减到负数，也不会被记「陌生」之外的档位；50 分默认不写 prompt，避免每次唤醒塞一串数字。
- 设置页只读（要改分数目前只能等控制台接口）；「手动调整」的 `applyDelta` 已经写好并有测试，等接 HTTP。
- 分档表在 `src/favor.js` 和 `plugins/surfcore/lib/index.js` 各有一份（跨包不能直接 import），
  **改一处必须改两处**——这是本 case 最容易踩的维护坑。

## v2（2026-11-02 晚）：加第二根轴「亲密」+ 四阶段

> 来源：用户把隔壁 AstrBot 的 **EmotionAI Pro 4.2.9** 源码丢过来（`astrbot_plugin_emotionai_pro-4.2.9`），
> 要求「参考一下」。四路子代理读完源码后，用户拍板：「直接落 P0：亲密轴 + 四阶段」，亲密衰减「加软顶：过 60 后每天 −0.2」。
> 设计稿见 [`docs/guides/RELATIONSHIP.md`](../guides/RELATIONSHIP.md)。

### 现象

- v1 只有一根轴：谁天天来、谁夸她，好感就高；但「聊了三句正事」和「聊了三个月」在数值上没有区别——
  一个刚认识就说了句谢谢的人，会跟老朋友拿同样的分。
- 用户原话（m00100 一带的投票）：选「直接落 P0：亲密轴 + 四阶段（推荐）」。
- 影响面：仍然只影响 prompt 里的两行字与设置页展示；不碰投递、不花钱、不丢数据；`favor.intimacy=false` 即回退 v1。

### 根因（为什么 v1 不够）

- 好感（favor）回答「喜不喜欢」，亲密（intimacy）回答「有多熟」。两者可以背离：很喜欢的陌生人、不太喜欢的老朋友。
  只有一根轴时，「升档」只能靠刷好感，于是**话多的人自动变成亲密的人**——这正是 EmotionAI Pro 用双轴修正的问题。
- 参考实现（`relationship_manager.py`）的双轴不是简单相加：先用固定探针 `0.6*favor + 0.4*intimacy` 判断落在哪一带，
  再用该带自己的权重称重；升档还要过亲密门槛，否则「高好感 + 低亲密」会卡在上一档（它叫 gate_blocked）。
  这个设计我们抄了，因为它是「不熟的人夸你一百句也还是不太熟」的数学表达。

### 完整逻辑

- **链路**：入站消息 → `noteFavorIncoming`（bridge.js）→ `observeMessage`（favor.js）
  → 好感打分（v1 规则不变）→ `noteIntimacy`（新增亲密信号）→ `settleStage`（升/降档判定）
  → `atomicWriteJson(state/favor/<角色>.json, version 2)` → 唤醒时 `favorPromptLine` → prompt【关系】段。
  设置页仍只读：`GET /dsh-surfcore/api/favor`，返回 `score/intimacy/composite/stage/nextThreshold/nextGate`。
- **机制**：
  - 探针定带：`probe = 0.6*favor + 0.4*intimacy`，逐档比较 `threshold - (已在这一带 ? downHysteresis : 0)`。
  - 称重：`composite = favorW*favor + intimacyW*intimacy`（生疏 0.7/0.3、熟识 0.5/0.5、亲近 0.35/0.65、默契 0.4/0.6）。
  - 升档双条件：`intimacy >= gate` **且** `composite >= threshold`；不满足则 `gated:true`、阶段不动。
  - 降档：`composite < 当前档 threshold - 5` 且**连续 7 天**都这样，才降一档；`stagePeak` 只涨不跌（到过哪里不会忘）。
  - **标签只写已经结算的档**：探针所在的带只决定「用哪套权重、要不要试着升档」，prompt 与设置页显示的始终是 `person.stage`。
    否则会出现「设置页写生疏、她读到的却是亲近」——同一个人两套说法，模型照着演就会失真（这一条是自测时发现的，已加断言锁死）。
  - 亲密信号（每轮最多 +2）：连续聊 ≥3 条 +1 / 单条 ≥40 字 +1 / 情绪浓度 ≥16 +1 / 共同约定 +2 / 道歉和好 +2 /
    深夜私聊 +1 / 连着好几天有深度互动 +1；冲突 −3（不受每日额度限制）。
  - 亲密不按天掉，只有**过 60** 才每天朝 60 回落 0.2（软顶）：熟过的人不会因为一周没聊就变回陌生人。
  - v1→v2 迁移：`intimacy = clamp(events*0.1 + 认识天数*0.2, 0, 40)`，随后 `settleStage` 补 `composite`；
    存档里的合法 `stage` 一律信任（基线自愈，参考实现线上踩过 favor=108 却显示"初见"的坑）。
- **爆炸半径**：2 个进程读同一份 JSON（桥接写、插件只读）× 1 文件；属性只增不改，v1 客户端读 v2 文件不会崩；
  失败仍在 `noteFavorIncoming` 的 try/catch 里 → 最坏是这一轮不涨关系，静默分 3。
- **取舍**：
  - A. 直接照抄 8 维情绪 + 每轮二次 LLM + 三套进度公式 → 贵、漂移、多套口径互相打架（参考实现自己就有三套进度和三个死字段）；
    B. 只抄「双轴 + 探针 + 门槛 + 迟滞」四条骨架，其余全用确定性规则（选中）。
  - A. 亲密也每天衰减 → 老关系会无端变淡；B. 软顶 60（选中，用户拍板）。
  - A. 降档即时生效 → 一次吵架就打回生疏；B. 连续 7 天 + 一次只降一档（选中）。
- **生效与重启**：`src/favor.js` 与 `src/bridge.js` 改动要**重启桥接**；`plugins/surfcore/lib/*` 改动要重启 DSH 让插件重载。
  老文件不需要手工迁移，第一次读入时自动补字段（**建议先备份 `state/favor/*.json`**：迁移会就地重写）。

### 修法

- `src/favor.js`：新增 `STAGES / stageIndex / stageOf / resolveStage / settleStage / noteIntimacy / stageHint`，
  `normalizeFavorConfig` 增 `intimacy/intimacyDayCap/intimacyColdDelta/intimacySoftCap/intimacyDecayPerDay/downHysteresis/downgradeDays`，
  `normalizeStore` 做 v1→v2 迁移 + 阶段自愈，`decay` 同时处理好感回归与亲密软顶，`promptBlock` 改成双轴行。
- `src/bridge.js`：`noteFavorIncoming` 传 `isGroup`（深夜私聊判定）。
- `plugins/surfcore/lib/index.js`：`handleFavor` 输出双轴 + 阶段 + 距下一档差值；老文件没有 `composite` 时按当前档权重**现算展示值**（不写回）。
- `plugins/surfcore/lib/client.js`：好感度页显示「好感 X　亲密 Y（阶段 · 认识 N 天）」与「升下一档还差」。
- 回滚：`favor.intimacy=false`（保留好感、关掉第二轴）；或 `git checkout src/bridge.js plugins/surfcore/lib/{index,client}.js`
  —— 注意 `src/favor.js` 目前还是**未入库的新文件**（`git status` 显示 `??`），回退到 v1 只能从 `~/.dsh/_quarantine/`
  或改动前备份里恢复，别指望 `git checkout`；`state/favor/*.json` 里 v2 字段可留着，v1 代码会忽略它们。
